# dsh-persona-curiosity

> 让 AI 主动问人，把「你是谁」慢慢问出来。

---

## 一、为什么做这个

现在的 AI 有一个根本问题：**它知道的都是你主动告诉它的**。

你问它问题，它回答；你不说，它就不问。

但人和人不是这么建立关系的——真的了解一个人，靠的是**问**，不是**等**。

这个插件想做的事很简单：

> 让 AI 主动问，从回答里一点点攒出「这个人是谁」。

---

## 二、它做什么

### 1. 攒问题

AI 在刷视频、看评论、回私信的过程中，会攒出「想问这个人的问题」。

问题不是查户口，是**能引出真实想法**的那种：

```
× "你多大了？"
× "你做什么工作的？"
√ "你说「钱够用就行」——那个「够」字，在你心里是长什么样的？"
√ "你更怕「做错」还是「错过」？"
√ "你上一次特别想找个人说话，是因为什么？"
```

### 2. 挑时机问

| 平台 | 怎么问 |
| --- | --- |
| **B站** | 回复评论 / @ / 私信时，结尾自然带一个问题 |
| **QQ 群** | 每 30 分钟，主动发一条 `【问一下】...` |
| **QQ 私聊** | 同上 |

### 3. 从回答里学

每收到一个回答，提取 **11 类人格信号**：

```
重视家庭        "孩子出生以后，钱够用就行，家人健康比什么都重要"
在意钱/生活压力  "房贷压得慌"
努力/不服输      "还是不甘心，想拼一下"
躺平/疲惫        "累了，躺平了，不想卷了"
爱技术           "这个原理我搞懂了"
爱游戏           "今晚开黑"
重感情           "分手以后好久没缓过来"
现实             "社会就是这样"
孤独             "一个人待着挺好的"
好奇心           "为什么？"
压力/负面情绪    "最近好烦"
```

**带否定词排除**：`"不想卷了"` 不会被误判成「努力」。

### 4. 记住是「谁」

同一个人在 B站 和 QQ 上是两个身份：

```
B站 uid 397565739  ←┐
                     ├→ owner（同一个人）
QQ uid 1951194537  ←┘
```

关联后，**两个平台的画像会合并**。

## 三、三个部分

### ① DSH 插件（本地）

7 个工具：

| 工具 | 作用 |
| --- | --- |
| `curiosity_ask` | 提一个问题入队 |
| `curiosity_mark_asked` | 标记已问 |
| `curiosity_answer` | 记录回答 + 提取信号 |
| `curiosity_list` | 看队列 |
| `curiosity_persona` | 看画像 |
| `curiosity_link` | 跨平台关联 |
| `curiosity_identities` | 查关联 |

### ② AstrBot 插件（云端 QQ）

| 插件 | 作用 |
| --- | --- |
| `intent_guard` | 判断「要不要回」+ 主动提问（30 分钟 / 12 次 / 天） |
| `persona_collector` | 每句话提取人格信号 |

### ③ B站 服务（云端）

| 模块 | 作用 |
| --- | --- |
| `persona_sink.py` | 评论 / 私信 → 人格信号 |

## 四、数据流

```
┌─ B站 ──────────────────────────────┐
│  粉丝：「最近加班好累，房贷压力大」  │
│         ↓ persona_sink 提取         │
│  bili_insights.json（云端）         │
└─────────────────────────────────────┘
                ↓
┌─ QQ ───────────────────────────────┐
│  你：「累死了」                     │
│         ↓ persona_collector 提取    │
│  insights.json（云端）              │
└─────────────────────────────────────┘
                ↓ sync-persona.cjs
┌─ 本地统一人格库 ────────────────────┐
│  insights.json                      │
│  links.json（跨平台关联）            │
└─────────────────────────────────────┘
                ↓
        curiosity_persona 查询
```

## 五、技术亮点

### 1. 规则提取，不依赖大模型

信号提取用的是**正则 + 否定词排除**，不用调 LLM：

```javascript
SIGNAL_RULES = [
  [/家人|父母|孩子|老婆|家庭/, "重视家庭"],
  [/钱|工资|房贷|够用|生活压力/, "在意钱/生活压力"],
  ...
]
NEGATIONS = ["不", "没", "别", "无", "未", ...]
```

**好处**：快、免费、可预测。

### 2. 跨平台关联用「canonical」

不是自动识别（B站 uid 和 QQ uid 之间没有天然映射），而是**人工指定**：

```javascript
curiosity_link({ canonical: "owner", platform: "bilibili", uid: "397565739" })
curiosity_link({ canonical: "owner", platform: "qq", uid: "1951194537" })
```

**合并发生在查询时**，原始数据不被破坏，随时可以改关系。

### 3. 三源同步，按 id 去重

```javascript
// 云端 QQ + 云端 B站 + 本地已有
// 合并时按 id 去重，不重复、不覆盖
```

### 4. 问题池分层

```
第一层：questions.json 里 status=pending 的问题（人工攒的）
第二层：内置 30 个问题（云端没有第一层时用）
```

## 六、怎么用

### 部署

```bash
git clone https://github.com/bojunmo/dsh-persona-curiosity
```

- DSH 插件：把 `index.js` / `lib/` / `package.json` 放进插件目录
- AstrBot 插件：把 `astrbot-plugin/*/` 放进 `/opt/astrbot/data/plugins/`
- B站 服务：把 `bili-duty-cloud/persona_sink.py` 放进 `/opt/bili-duty/`

### 日常

```powershell
# 同步人格库（云端 → 本地）
node sync-persona.cjs

# 或者在 DSH 里问
curiosity_persona
```

## 七、和别的人格插件有什么不同

| 常见做法 | 这个插件 |
| --- | --- |
| 被动记录聊天 | **主动问问题** |
| 单平台 | **B站 + QQ 跨平台** |
| 泛泛的「性格标签」 | **具体的、带原话的信号** |
| 一次性的 | **持续的、会忘记也会更新** |
